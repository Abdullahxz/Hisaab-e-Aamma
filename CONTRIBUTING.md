# Contributing

Thanks for helping make Pakistan's public finances more understandable. This
document covers the technical side: architecture, the data pipeline, and — most
importantly — the **accuracy rules** every change must respect.

By contributing you agree that your contributions are licensed under the
project's [Apache-2.0](LICENSE) licence.

## Ground rule: accuracy beats everything

This project's value is that its numbers can be trusted. Run `npm run check`
before opening a PR — it enforces the invariants below and is the same gate CI
runs before any deploy. Every contribution must preserve them:

- **Every figure cites its source** — document id, table, and page — and the
  citation must point at the exact page in the official PDF.
- **Everything reconciles.** The Sankey balances exactly (resources into the
  pool = expenditure out = Rs 18,771.417 bn). A parent node's value equals the
  sum of its children (±Rs 1.5 bn rounding tolerance). Parsed tables are only
  shipped when they sum to their printed totals.
- **Never guess.** If a figure can't be verified, omit it and say so in the UI.

## Stack

- [Vite](https://vitejs.dev) 5 + React 18 (JavaScript, `.jsx`), `@` alias → `src/`
- [d3-sankey](https://github.com/d3/d3-sankey) for **layout math only** — the
  SVG is rendered declaratively by React (d3 never touches the DOM)
- [framer-motion](https://www.framer.com/motion/) for node/link morph animations
- Tailwind CSS 3.4 + vendored [shadcn/ui](https://ui.shadcn.com)-style
  components in `src/components/ui/`
- Fully static build (`npm run build` → `dist/`), deployable to any static host

```bash
npm install     # a project .npmrc pins the public npm registry
npm run dev     # dev server
npm run build   # production build
```

## Architecture

```
public/data/budget.json      # the Sankey dataset (single source of truth)
public/data/ministries.json  # ministry explorer dataset (generated by scripts)
public/og-image.png          # 1200x630 social preview card
scripts/parse-mtbf.mjs       # Green Book -> ministries.json
scripts/parse-demands.mjs    # Demands for Grants -> per-demand object splits
src/
  App.jsx                    # state + hash router (see Routes below)
  components/
    SankeyChart.jsx          # d3-sankey layout -> animated SVG
    DetailSheet.jsx          # slide-in panel: description, YoY, breakdowns, source
    MinistriesPage.jsx       # object-classification card + ministry list
    MinistryPage.jsx         # goal/outcomes, 5-year outputs, per-demand objects
    TaxReceiptPage.jsx       # personalised "where your income tax goes"
    BasicsPage.jsx           # plain-language primer + glossary
    bits.jsx                 # shared DeltaBadge / SourceLine / SourceCard / ObjectInfo
    ui/                      # vendored shadcn primitives
  lib/
    buildGraph.js            # hierarchical data + expansion state -> {nodes, links}
    objectInfo.js            # plain-language text for object heads A01…A13
    validateData.js          # dev-time balance & source checks (browser console)
    format.js, palette.js, utils.js
```

### Routes & shareable deep links

| Hash | Page |
|---|---|
| `#/` | budget flow (Sankey) |
| `#/?e=<ids>&s=<id>` | flow with expanded nodes + selected node restored |
| `#/ministries` | ministry list + federal object classification |
| `#/ministry/<slug>` | one ministry |
| `#/receipt` | personal tax receipt |
| `#/basics` | budget basics & glossary |

Flow state is mirrored into the hash with `history.replaceState` (no history
spam, no `hashchange` feedback loop) and read back on every navigation, so the
address bar is always a working share link. A selected node's ancestors are
auto-expanded so a pasted link can't land in an impossible state; unknown ids
are ignored rather than erroring.

### Deploying

**CI and GitHub Pages are automated** via `.github/workflows/deploy.yml`:

| Event | What runs |
|---|---|
| **Pull request** → `main` | `npm ci` → `npm run check` → `npm run build`. Verified only — **never published**. |
| **Push/merge** → `main` | The same, then builds with the real Pages URL and deploys. |
| **Manual** (Actions tab) | Same as a push — for re-deploying without a code change. |

`npm run check` runs *before* the build in every case, so a data change that
breaks reconciliation fails the pull request instead of being discovered after
it merges. The deploy step reads the real published URL from
`actions/configure-pages` and passes it as `SITE_URL`, so social-preview tags
are always correct — including if you later attach a custom domain. On pull
requests that step is skipped, so the build logs a harmless "SITE_URL is not
set" warning and uses relative URLs.

One-time setup: repo **Settings → Pages → Source: GitHub Actions**. Worth also
enabling branch protection on `main` (**Settings → Branches**) requiring the
*Check data & build* job to pass — otherwise a red check is only advisory and a
PR can still be merged.

### Analytics (optional, off by default)

Cookieless [Umami](https://umami.is) pageview counting, enabled per build by
`UMAMI_WEBSITE_ID`. In CI it comes from a repo **variable** (Settings → Secrets
and variables → Actions → Variables) and is deliberately blank on pull
requests, so PR builds never report into the production dashboard. Local and
fork builds have no analytics unless you set the variable yourself.

```bash
UMAMI_WEBSITE_ID=<uuid> npm run build      # Umami Cloud
UMAMI_SCRIPT_URL=https://…/script.js …     # override for a self-hosted instance
```

**Umami setup note:** the Domain field wants a bare hostname
(`abdullahxz.github.io`) — no protocol, no path. Collection is keyed by the
website id, not the domain, so several sites can share one hostname and still
report separately.

⚠️ **`data-auto-pageview="false"` is deliberate**;
pageviews are sent manually from `src/lib/usage.js`. The flow view mirrors
chart state into the URL via `history.replaceState` on every expand and
selection, and Umami's auto-tracker patches `replaceState` — leaving it on
records a pageview for *every click on the chart* and floods the report with
thousands of distinct `?e=…&s=…` URLs. Pageviews are therefore sent once per
logical route, with chart state stripped to a canonical path (`/`,
`/ministries`, `/ministry/<slug>`, `/receipt`, `/basics`). **If you add a
route, add it to `canonicalPath()`.**

### Hosting elsewhere

For any other host, the build is path-agnostic (`base: './'`), so `dist/` can
be served from any origin and any sub-path without configuration — **except**
the social-preview tags.

**Why the one exception:** link-preview crawlers (Twitter/X, Slack, WhatsApp,
LinkedIn, Facebook) fetch the raw HTML and **do not execute JavaScript**, so
`og:image` / `og:url` cannot be filled in at runtime, and they need absolute
URLs. The deploy origin is therefore injected at build time:

```bash
SITE_URL=https://your.domain npm run build          # root of a domain
SITE_URL=https://you.github.io/repo npm run build   # project sub-path
```

You can also put `SITE_URL=…` in a `.env` file (it is read via `loadEnv`, so
either works). A trailing slash is fine — it gets normalised.

If `SITE_URL` is omitted the build still succeeds and prints a warning: the
image falls back to a relative URL (most crawlers resolve it; Twitter/X may
not) and `og:url` is dropped rather than emitted empty. Everything else —
including the in-app "Copy link" button, which uses `window.location.href` —
is fully dynamic and needs no configuration.

Regenerate `public/og-image.png` by rendering a 1200×630 page in the same
palette if you restyle the site.

### The Sankey dataset (`public/data/budget.json`)

- `sources[]` — the official documents. Each has an `officialPdf` URL pointing
  to the Finance Division's own copy (verified byte-identical to the copies the
  data was extracted from, and served inline so `#page=N` deep links work).
  Citations link there; `file` is kept as a fallback reference.
- `structuralLinks[]` — the fixed backbone flows (revenue → gross → pool →
  spending).
- `nodes[]` — every box: `id`, `label`, `side` (`receipt`|`hub`|`transfer`|
  `expenditure`), `parent`, `value` (Rs **billion**, BE 2026-27), `prior`
  (BE 2025-26), `revised` (RE 2025-26), `description`, `source` `{docId, page,
  table}`. Optional: `facts[]` (key-value cards, e.g. the NFC formula) and
  `altBreakdowns[]` (alternative views that need not sum to the node, e.g.
  function-wise or gross-vs-net tables).

To change a number: edit the node's `value` — and keep parents equal to the
sum of their children. `validateData.js` logs violations to the console on load.

### Percentages have two denominators (deliberate)

Revenue-side amounts show "% of gross revenue" (FBR 74% + non-tax 26% = 100%);
everything else shows "% of the total budget". Gross revenue exceeds the budget
because a large slice passes through to the provinces, so a single denominator
produces misleading >100% values. See `percentInfo` in `buildGraph.js`.

## The data pipeline (regenerating `ministries.json`)

The source PDFs are not committed (they're ~30 MB and belong to the
government). Download them from
<https://www.finance.gov.pk/fb_2026_27.html> into the repo root, then:

```bash
# 1. extract text (poppler required: brew install poppler)
pdftotext -layout Medium_Term_Performance_Based_Budget.pdf /tmp/mtbf.txt
for v in I II III IV; do
  pdftotext -layout "Detail_of_Demands_for_Grants_Vol-$v.pdf" "/tmp/dfg$v.txt"
done

# 2. run order matters: mtbf regenerates the file, demands patches it
node scripts/parse-mtbf.mjs /tmp/mtbf.txt
node scripts/parse-demands.mjs /tmp/dfgI.txt /tmp/dfgII.txt /tmp/dfgIII.txt /tmp/dfgIV.txt
```

Notes: these PDFs do **not** rasterise (pages render blank), so verification is
done by cross-table reconciliation of the text layer, not by eyeballing images.
`pdftotext -layout` preserves column x-positions, which the parsers depend on.

### Parser design (hard-won — don't regress)

`parse-mtbf.mjs` (Green Book → per-ministry services):
- Sections are found by `PAO:` lines; PDF page numbers come from counting `\f`.
- All cells are integers in Rs '000 — every `.`/`,` is a separator (the source
  contains typos like `10.903,000`).
- Tokens map to year columns by **order-preserving minimum-cost alignment**
  (immune to the column shifts on continuation pages).
- Logical rows wrap across physical lines; a line's tokens merge into the
  previous row when they all fit still-empty columns.
- Names come from text segments left of the midpoint between the "Outputs" and
  "Office" header tokens (office cells start left of their own header).
- Prose digits must never become values: tokens require position ≥ the name
  boundary AND comma-grouping or ≥1,000.
- A Total row may span 3 physical lines — the adjacent nameless row merges in.
- **Reconciliation gate:** an outputs table ships only if every year column
  sums to the printed Total (±0.1%); otherwise the UI shows verified totals
  with an honest note. (Known source quirk: Defense Division's printed total
  excludes its own development row — it legitimately fails.)

`parse-demands.mjs` (Demands volumes → per-demand object classification):
- Values are in full rupees (÷1e9 → bn). Vol-I covers demands 1–42, Vol-II
  43–67, Vol-III 68–91, Vol-IV 92–135 (development).
- **Double gate:** major object heads (A01…A13) must sum to the demand's
  printed Total in every year column, **and** the 2026-27 total must match the
  independently transcribed Budget in Brief Table 21 figure (`T21_EXPECTED`).
  130/135 demands pass; failures are skipped loudly and never shipped.
- Ministry ↔ demand mapping is the hand-curated `DEMAND_MAP` (top ministries).

## Verifying UI changes

Always look at the result — the checks catch data errors, not layout ones.
`puppeteer-core` (using system Chrome) is a devDependency; the pattern is:
start `npm run dev`, drive the page, click nodes by matching `.node-label`
text, screenshot landing / expanded / deep-drill / both themes, and assert the
detail sheet is absent on landing and closes on Escape.

After any data change:

```bash
node --input-type=module -e '
import { readFileSync } from "fs";
const b = JSON.parse(readFileSync("public/data/budget.json","utf8"));
const i = b.structuralLinks.filter(l=>l.target==="total_resources").reduce((a,l)=>a+l.value,0);
const o = b.structuralLinks.filter(l=>l.source==="total_resources").reduce((a,l)=>a+l.value,0);
console.log("balance diff:", (i-o).toFixed(3)); // must be 0.000
'
```

## Design system

The four role colors (receipt `#1baf7a`, expenditure `#eb6834`, transfer
`#4a3aa7`, hub `#64748b`, with dark-mode variants) are colorblind-safe and
contrast-validated as a set — don't swap hues casually. Node labels always
render with a surface-colored halo (`.node-label` in `src/index.css`); that is
the contrast mitigation for the light-mode aqua, so keep labels visible. Both
light and dark themes must stay polished (`data-theme` on `<html>`).
