# Contributing

Thanks for helping make Pakistan's public finances more understandable. This
covers the technical side: how to run it, how the data is regenerated, and the
accuracy rules every change must respect.

By contributing you agree that your contributions are licensed under the
project's [Apache-2.0](LICENSE) licence.

## Ground rule: accuracy beats everything

Run `npm run check` before opening a PR. It enforces the invariants below and is
the same gate CI runs before any deploy.

- **Every figure cites its source**, down to the document, table and page, and
  the citation links to that exact page of the official PDF.
- **Everything reconciles.** The Sankey balances at Rs 18,771.417 bn, a parent
  node equals the sum of its children (±1.5 bn rounding), and parsed tables ship
  only when they sum to their printed totals.
- **Never guess.** If a figure can't be verified, omit it and say so in the UI.
- **Say what the numbers are not.** This is the federal budget: provinces pass
  their own budgets from their NFC share, and the federal PSDP is only part of
  national development spending. Copy that could read as a national total must
  carry that caveat.

## Stack and layout

[Vite](https://vitejs.dev) 5 + React 18 (JavaScript `.jsx`, `@` alias to
`src/`), [d3-sankey](https://github.com/d3/d3-sankey) for layout maths only,
[framer-motion](https://www.framer.com/motion/) for the morph animations,
Tailwind 3.4 with vendored [shadcn/ui](https://ui.shadcn.com) components on
Radix. Fully static build, deployable anywhere.

```bash
npm install     # a project .npmrc pins the public npm registry
npm run dev
npm run check   # data invariants
npm run build   # -> dist/
```

```
public/data/budget.json      # the Sankey dataset (single source of truth)
public/data/ministries.json  # ministry dataset, GENERATED by scripts/
scripts/                     # check-data + the two PDF parsers
src/App.jsx                  # hash router + all chart state
src/components/              # SankeyChart, DetailSheet, the four pages,
                             #   bits.jsx (badges, citations, ⓘ popovers), ui/
src/lib/                     # buildGraph, validateData, format, palette,
                             #   objectInfo, usage (analytics), site, utils
```

| Hash | Page |
|---|---|
| `#/` and `#/?e=<ids>&s=<id>` | budget flow, optionally with expanded/selected nodes restored |
| `#/ministries`, `#/ministry/<slug>` | ministry list and detail |
| `#/receipt` | personal tax receipt |
| `#/basics` | glossary and primer (first nav tab, labelled "Glossary") |

Flow state is mirrored into the hash with `history.replaceState`, so no history
spam and no `hashchange` loop. A selected node's ancestors are auto-expanded, so
a pasted link can't land in an impossible state; unknown ids are ignored.

## The Sankey dataset

`nodes[]` carries `id`, `label`, `side` (`receipt`/`hub`/`transfer`/
`expenditure`), `parent`, `value` (Rs billion, BE 2026-27), `prior`, `revised`,
`description` and `source {docId, page, table}`. Optional `facts[]` (key-value
cards, e.g. the NFC formula) and `altBreakdowns[]` (alternative views such as
function-wise or gross-vs-net) render in the detail sheet and need not sum to
the node. `structuralLinks[]` holds the fixed backbone flows.

To change a number: edit the node's `value`, keep the parent equal to the sum of
its children, and run `npm run check`. `validateData.js` logs the same problems
to the browser console on load.

Percentages use two denominators deliberately: revenue-side amounts show "% of
gross revenue", everything else "% of the total budget". Gross revenue exceeds
the budget because a large slice passes to the provinces, so a single
denominator produces misleading values over 100%.

## Regenerating `ministries.json`

The source PDFs aren't committed (about 30 MB, and they belong to the
government). Download them from <https://www.finance.gov.pk/fb_2026_27.html>
into the repo root, then (poppler required: `brew install poppler`):

```bash
pdftotext -layout Medium_Term_Performance_Based_Budget.pdf /tmp/mtbf.txt
for v in I II III IV; do
  pdftotext -layout "Detail_of_Demands_for_Grants_Vol-$v.pdf" "/tmp/dfg$v.txt"
done

# run order matters: mtbf rewrites the file, demands patches it
node scripts/parse-mtbf.mjs /tmp/mtbf.txt
node scripts/parse-demands.mjs /tmp/dfgI.txt /tmp/dfgII.txt /tmp/dfgIII.txt /tmp/dfgIV.txt
```

These PDFs do not rasterise, so verification is cross-table reconciliation of
the text layer, never eyeballing rendered pages. `pdftotext -layout` preserves
column x-positions, which both parsers depend on.

### Parser design (hard-won, don't regress)

`parse-mtbf.mjs` (Green Book to per-ministry services):

- Sections start at `PAO:` lines; page numbers come from counting `\f`.
- Cells are integers in Rs '000, so every `.`/`,` is a separator (the source
  contains typos like `10.903,000`).
- Tokens map to year columns by order-preserving minimum-cost alignment, which
  survives the column shifts on continuation pages.
- Logical rows wrap across physical lines and merge when their tokens fit
  still-empty columns; a Total row can span three lines.
- Prose digits must never become values: a token needs position past the
  name/office boundary and comma-grouping or a value ≥ 1,000.
- **Reconciliation gate:** an outputs table ships only if every year column sums
  to the printed Total (±0.1%), otherwise the UI shows the verified totals with
  an honest note. 54/67 reconcile. Defense Division legitimately fails: its own
  printed total excludes its development row.

`parse-demands.mjs` (Demands volumes to per-demand object classification):

- Values are in full rupees. Vol-I covers demands 1-42, Vol-II 43-67, Vol-III
  68-91, Vol-IV 92-135.
- **Double gate:** object heads A01-A13 must sum to the demand's printed Total
  in every year column, *and* the 2026-27 total must match the independently
  transcribed Budget in Brief Table 21 figure. 130/135 pass; failures are
  skipped loudly and never shipped.
- The ministry-to-demand mapping is the hand-curated `DEMAND_MAP`.

## Verifying UI changes

The checks catch data errors, not layout ones, so look at the result.
`puppeteer-core` (driving system Chrome) is a devDependency: start `npm run dev`,
click nodes by matching `.node-label` text, and screenshot landing, expanded and
deep-drill states in both themes. Note that StrictMode double-invokes effects in
dev, so anything effect-driven should be confirmed against `npm run preview`.

## Deploying

`.github/workflows/deploy.yml` handles CI and GitHub Pages:

| Event | What runs |
|---|---|
| Pull request | `npm ci` → `npm run check` → `npm run build`, verified only, never published |
| Push to `main` | the same, then builds with the real Pages URL and deploys |
| Manual | same as a push |

`npm run check` runs before the build in every case, so a data change that
breaks reconciliation fails the PR instead of production. One-time setup:
**Settings → Pages → Source: GitHub Actions**, and branch protection on `main`
requiring the *Check data & build* job.

**Social tags need `SITE_URL`.** Link-preview crawlers don't run JavaScript and
need absolute URLs, so the origin is baked in at build time. CI passes the real
Pages URL automatically; elsewhere:

```bash
SITE_URL=https://your.domain npm run build   # or put it in .env
```

Without it the build still succeeds, warns, falls back to a relative image and
drops `og:url`. Everything else is path-agnostic (`base: './'`), so `dist/`
serves from any origin or sub-path. Regenerate `public/og-image.png` (1200×630)
if you restyle the site.

## Design system

Four role colours (receipt `#1baf7a`, expenditure `#eb6834`, transfer `#4a3aa7`,
hub `#64748b`, plus dark variants) are colourblind-safe and contrast-validated
as a set, so don't swap hues casually. Node labels always render with a
surface-coloured halo, which is the contrast mitigation for the light-mode aqua.
Both themes must stay polished (`data-theme` on `<html>`).

**Copy style:** user-facing text carries no em dashes, no inline `<strong>` in
body copy (bold marks structure only), and `n/a` for a missing value. This
covers component text, both datasets and the `index.html` meta tags; strings
shipped into `ministries.json` live in the parser scripts, so change them there.
Code comments are exempt.
